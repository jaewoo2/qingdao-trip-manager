# 검증 결과와 한계

## 검증 범위

공개용 예시 데이터로 변경한 앱을 별도 체크아웃에서 설치하고 검증합니다. Node.js 24 · npm 11 · Chromium을 사용합니다. 비밀키·서버·DB를 요구하지 않습니다.

| 확인 항목 | 결과 |
|---|---|
| 고정 lockfile 설치 `npm ci` | 통과 |
| ESLint·TypeScript | 통과 |
| 단위·컴포넌트 테스트 | 6개 파일 · 39건 통과, 실패·skip 없음 |
| 프로덕션 빌드 | TypeScript·Vite·Service Worker 빌드 통과 |
| Chromium E2E | 18건 통과, 실패·skip 없음 |
| 공개 파일 검사 | 예시 데이터·주요 비밀정보 패턴·배포 주소 검사 통과 |
| GitHub Actions | 설정 포함, 원격 실행 결과는 이 문서에서 보장하지 않음 |

## 자동 검증 내용

- 기본 일정과 대안 원복, 허용되지 않은 장소 선택 거부
- 메모·식당 선택·준비물·완료의 저장과 백업·복원
- 손상된 저장소 보존, 저장 공간 실패 안내
- 인터넷 차단·서버 중지 후 캐시 재실행과 편집
- Service Worker 업데이트 후 메모·선택·선택 날짜 유지
- 식당 선택과 메뉴·그림·주소·고덕 검색 대상 일치
- 320/375/430px 3열 정사각형 앨범, 상세 팝업·이미지 갤러리
- 하루 전체 완료/해제, 개별 체크와의 일치, 지난 일정 분류
- 이후 날짜에도 연결된 후보의 진행 중 목록 유지
- 예시 숙소·항공 데이터와 미확인 지도 식별자 기본값

## iPhone 확인은 구분해서 기록

프로젝트 제작자는 **개인용 선행 버전**을 실제 iPhone에서 사용하고 모바일 UI, 고덕지도 연동, 오프라인 사용이 잘 동작한다고 보고했습니다. 이는 사용자 보고이며, 공개 예시 앱을 새로 설치해 별도로 실기기 시험한 결과는 아닙니다.

정확한 기기·앱 버전별 기록과 모든 장소·이동수단의 현재 위치 출발/목적지/경로 결과 조합을 수집한 상태는 아닙니다. 공개 데이터의 `routeVerifiedOnIPhone` 등 검증 플래그를 이 보고만으로 올리지 않았습니다. 합성 테스트 ID와 좌표는 직렬화 검증용이며 실제 장소 데이터가 아닙니다.

## 남은 한계

- 공개 예시 앱의 실제 iPhone 설치·강제 종료·오프라인 재실행은 배포 후 별도 확인 필요
- 식당의 최신 영업·지점·메뉴·대기는 독립적으로 재확인하지 않음
- 고덕지도 앱/브라우저/iOS에 따른 외부 앱 전환 차이 존재
- 사이트 데이터 삭제나 기기 정리 시 캐시·로컬 변경이 소실될 수 있음
- 동행자 동기화, 자유 일정 편집, 새 식당 등록은 미구현

설치·실기기 확인 순서는 [사용 안내](getting-started.md)를 따릅니다. 단위 테스트나 Chromium 통과를 iPhone 실기기 검증으로 표현하지 않습니다.

## 실행 기록

2026-10-15 클라우드의 별도 공개용 체크아웃에서 검증했다. 예시 숙소의 중국어명을 비운 후 테스트용 합성 장소명도 명시하도록 수정했다. 예시 날짜의 괄호를 정규식으로 해석하던 날짜 선택자와 남은 이전 날짜/날씨 제목 선택자를 보완한 뒤 전체 검사를 다시 실행해 통과했다.

비차단 빌드 경고: 아이콘 라이브러리의 use client 지시문, PWA 번들러 옵션의 deprecation, 전이 개발 의존성 glob 안내가 있다. 이를 실제 실패나 iPhone 검증으로 혼동하지 않는다.
