# 예시 데이터 수정과 배포

## 현재 데이터를 바꾸려면

지금은 개발자가 파일을 수정하는 방식입니다. 앱 화면에서 식당을 자유롭게 추가하는 편집기는 아직 없습니다.

1. `src/data/itinerary.seed.json`: 여행 정보·날짜·일정·장소를 수정합니다.
2. `src/lib/tripPlan.ts`: 식당 기본값과 허용 대안을 확인합니다. seed보다 이 계획 계층의 값이 우선할 수 있습니다.
3. `src/data/restaurants.ts`: 식당 설명·메뉴·참고 출처를 수정합니다.
4. `src/data/restaurantIllustrations.ts`: 직접 사용할 권한이 있는 그림을 연결합니다.
5. UI에 남아 있는 예시 안내와 `tripId`/상태 스키마를 함께 확인하고 테스트합니다.

현재 데이터 모델과 완료 ID 검증은 4일·35개 이벤트 예시에 맞춰져 있습니다. 행사 수나 여행 기간을 바꾸는 것은 단순 JSON 변경만으로 완료되지 않으며 스키마·사용 상태·화면·테스트를 함께 조정해야 합니다.

새 장소의 좌표나 POI ID를 추정해서 채우지 마세요. 중국어 상호·주소·검색어만 있어도 검색·복사 기능을 먼저 사용할 수 있습니다.

## 직접 배포하기

`npm ci` 후 `npm run build`의 `dist/`를 HTTPS 정적 호스팅에 올립니다. Service Worker 때문에 HTTPS가 필요하며 로컬 개발 주소는 브라우저의 예외 규칙을 따릅니다.

이 앱은 **도메인 루트(`/`) 배포를 전제**합니다. GitHub Pages의 저장소 하위 경로에 그대로 올리면 Vite base뿐 아니라 manifest·Service Worker·정적 자산 경로를 함께 조정해야 합니다. 이 저장소는 배포를 자동 실행하지 않습니다.

HTTPS 배포 후 iPhone Safari에서 홈 화면에 추가하고 실제 설치 앱의 캐시·재실행·저장 상태를 검증하세요. 인증을 사용하는 호스팅은 manifest/아이콘/SW 다운로드와 인증 만료 후 오프라인 실행도 별도로 확인해야 합니다.

사이트 주소가 바뀌면 로컬 데이터가 자동 이전되지 않습니다. 필요한 기록은 기존 사이트에서 JSON 백업 후 새 사이트에서 복원합니다.
